## 1. 이 앱이 하는 일과 선생님이 바라는 것

- **누구를 위한 앱인가**: 중1 기초학력 방과후 학생 5명 내외(주 1회 대면 50분 + 주중 웹앱 하루 10분). 목표 점수 20점 → 40점 → 60점.
- **제1목표**: 학생이 **스스로 이해하고 성장**하는 것. 화려함, 기능 수, 게임성보다 이게 먼저예요.
- **기술 조건**: 빌드 도구 없는 순수 HTML/CSS/JS, GitHub Pages로 바로 배포, 저장은 `localStorage` + Supabase(`DB` JSON, 300KB 한도). Webpack·Vite·TypeScript를 넣지 않아요.
- **시험 범위 15차시**: Ⅳ 좌표평면과 그래프(`coord`·`graph`·`prop`·`inv`) · Ⅵ 원과 부채꼴(`arc`·`cent`·`sector`) · Ⅶ 입체도형(`poly`·`regular`·`rotation`·`rotprop`·`area`·`volume`·`conearea`·`cone`).
- **차시 한 개 = 3탭 × 3걸음**: `개념 보기 · 유형 익히기 · 차시 마무리` × `🌱 첫걸음 · 🌿 한걸음 · 🌳 두걸음`. 이 틀은 공용 엔진이 그리고, 차시 파일은 내용(문제·그림·장면)만 등록해요.

## 2. 코드 지도 — 어디를 고치면 되나

### 2-1. 차시 파일 (내용) — 차시별로 나눠 맡는 곳

| 차시 id | 걸음 내용(🌱🌿🌳, 부엉 쌤 장면, 복합 문제) | 문제 생성기(`GEN`·`PTYPES`) |
| :--- | :--- | :--- |
| `arc` · `sector` | `js/02t-tracks-circle.js` | `js/06c-unit-circle.js` |
| `cent` | `js/02t-tracks-cent.js` | `js/06c-unit-circle.js` |
| `poly` · `regular` · `area` · `volume` | `js/02t-tracks-solid.js` | `js/02-unit-solid.js` |
| `rotation` · `rotprop` | `js/02t-tracks-solid.js` | `js/02r-solid-rot.js` |
| `conearea` · `cone` | `js/02t-tracks-solid.js` | `js/02v-solid-vol.js` |
| `coord` · `graph` · `prop` · `inv` | `js/02t-tracks-graph.js` | `js/06d-unit-graph.js` |

- 각 `02t-tracks-*.js`는 `HG_TRACKS.register('차시id', { … })`로 차시를 등록해요. 안에 든 것: `kind`(`'concept'` 개념형 / `'proc'` 절차형), `owlScenes`(🦉 부엉 쌤 그림극), `schemaRapid`(🌱 빠른 구별), `firstGuide`(🌱 따라 풀기), `t1Check`(🌱 마무리), `worked`(🌿 대표 예제), `compoundList`·`genCompound`(🌳 복합).
- **한 파일에 여러 차시가 들어 있어요**(`circle`=2차시, `solid`=8차시, `graph`=4차시). 같은 파일이라도 **다른 차시 블록**이면 나눠 맡을 수 있지만, 같은 파일을 두 에이전트가 동시에 고치면 합칠 때 충돌이 나기 쉬워요. 작업 보드에 "어느 차시 블록인지"까지 적어 주세요.
- 위 표는 테스트 계정의 📍 버튼 코드(`js/09-debug-loc.js`의 `SPEC_FILE`·`UNIT_FILE`)와 같아요. 새 차시를 만들면 그 표에도 한 줄 넣어요.

### 2-2. 공용 파일 — 한 번에 한 에이전트만

아래 파일은 모든 차시·화면이 같이 쓰는 **화면 틀과 공용 장치**예요. **한 번에 한 에이전트만** 고치고, 고치기 전에 작업 보드에 이름을 올려 "지금 내가 쓰는 중"임을 알려요. 다른 작업에서는 1~3줄 최소 훅만 허용해요.

| 파일 | 하는 일 |
| :--- | :--- |
| `js/02t-track-engine.js` | 『교과서 한 걸음』 3탭 × 3걸음 **화면 틀**(엔진): 진도 계산 `lessonProgressInfo`, 부엉 쌤 재생기 `mountOwlShow`, 빠른 구별 `renderT1Rapid`, 따라 풀기, 마무리, `[복습 추천]` |
| `js/01-core.js` | `DB` 저장·정리, 키패드·채점(`answerUI`, `check`), 단계 문제 렌더러, 용어 사전 |
| 단원 생성기 파일 (`06c`·`06d`·`02-unit-solid`·`02r`·`02v`) | 문제 생성기 `GEN.*`·`PTYPES`. 여러 걸음과 보스전이 같은 생성기를 불러 써요 |
| `index.html` · `styles.css` · `tracks-cent.css` | 화면 뼈대·스크립트 로드 순서(`01` → … → `07` → `08`)·공용 스타일 |

그 밖의 화면: 홈·단원·내 기록 `js/02-unit-solid.js`(`viewHome`·`viewUnit`·`viewMe`), 교사 화면 `js/03-teacher.js`, 게임·상점 `js/04-games.js`, 좌표 해전 `js/04s-sea.js`, 기초 연산·오늘의 계산 `js/05-calc.js`, 나의 길 `js/06g-goal.js`, 라우터·인쇄·OMR `js/07-print-omr-boot.js`. 자세한 표는 `AGENTS.md` 1절.

### 2-3. 새 차시·새 기능은 새 파일로

`js/02-unit-solid.js`(200KB 넘음)에 덧붙이지 말고, `(() => { … })()`로 감싼 **독립 파일**을 만들어 `index.html`에 1줄로 불러요. 전역 이름은 꼭 필요한 것만(`window.xxx`) 내놓아요.

## 3. 작업 흐름 (매번 이 순서)

1. **최신 받기**: `git fetch origin` 후 `origin/main` 기준으로 시작해요.
2. **누가 무엇을 하는지 보기** (충돌 방지)
   - `COLLAB.md` 작업 보드에서 상태가 '진행 중'·'대기'인 줄과 그 **허용 파일(Scope)**.
   - 열린 브랜치·PR: `agy/*`(Antigravity), `claude/*`(Claude Code) 등. `git ls-remote --heads origin`, GitHub 열린 PR 목록에서 **내가 고칠 파일을 건드리는 게 있는지** 확인해요. 있으면 그 파일은 피하거나, 그 작업이 머지된 뒤 시작해요.
3. **보드에 한 줄 올리기**: 새 ID(`T28`, `T29` … 마지막 번호 + 1), 작업 내용, 담당(내 이름), 허용 파일, 상태 `진행 중`. 이 줄만 먼저 커밋해 두면 다른 에이전트가 봐요.
4. **스펙 읽기**: 있으면 `docs/specs/Txx-*.md`. 문제·그림을 만든다면 아래 4절 판단 기준을 먼저 봐요.
5. **고치기**: 허용 파일만. 범위 밖 파일이 꼭 필요하면 1~3줄 훅으로 줄이고, 인계 메모에 적어요.
6. **검증**
   - `node tests/verify.mjs` 통과(GitHub Actions `Verify Hangeoreum Math`도 같은 검사).
   - **브라우저로 눈 확인**: 그림 방향(원호 `sweep-flag`)·글자 겹침·애니메이션 끝 모습·같은 화면에서 버튼 다시 누르기·휴대폰 폭(약 390px). 자동 검사가 통과해도 그림 오류는 못 잡아요.
7. **반영**: 커밋·PR 제목 맨 앞에 `[Txx]`(예: `fix(tracks): [T28] sector 첫걸음 보기 4개로`). PR 본문에 `작업 ID · 바뀐 파일 · 검증 결과 · 다음 작업자 메모(DB/HTML 훅 변경 여부)`.
8. **바로 머지**: 검증이 통과하면 **선생님 확인을 기다리지 않고** main에 머지해요. 선생님은 PR 미리보기가 아니라 **실제 사이트(GitHub Pages)에서 Ctrl+Shift+R 새로고침**으로 확인해요.
   - main에 직접 반영할 수 없는 환경이면 `[Txx]` PR만 올려요. 다른 에이전트(Antigravity)가 검증 후 대신 머지해요.
9. **선생님 손이 필요한 단계는 따로 알리기**: Supabase SQL 실행(`supabase/*.sql`), 운영 DB 설정, 교사 화면 설정처럼 AI가 못 하는 일은 **답장 맨 앞에** "선생님이 하실 일: …"로, 어디서 무엇을 누르는지까지 적어요. 적용 전에도 앱이 깨지지 않게(예: 서버 응답이 없으면 예전 화면) 만들어 두어요.
10. **마무리**: `COLLAB.md` 상태 `완료`, 인계 로그 맨 위에 날짜·작업 ID·한 단락 요약(무엇을, 왜, 새 DB 필드 여부, 남은 일).

## 4. 선생님의 판단 기준 (문항·화면을 만들 때)

원본은 선생님 프로젝트 폴더의 `notes/설계/한걸음수학-설계-제작-규칙-총정리.md`(단일 기준)와 `notes/문항제작-유의점-걸음별.md`예요. 저장소에는 없어서, 꼭 지킬 것만 여기에 옮겨 둬요.

### 4-1. 가장 먼저 지킬 것
1. **말한 범위만 고쳐요.** 선생님이 "이것만", "이 차시만"이라고 하면 그 문항·차시만. 다른 곳까지 넓힐지는 따로 여쭤요.
2. **정답을 알려 주는 힌트는 없어요.** 힌트 사다리는 ① 무엇을 묻나 → ② 성질/식 고르기 → ③ 첫 줄 빈칸까지. 마지막 도움은 `선생님 풀이 보기`이고, 본 뒤엔 비슷한 새 문제가 나와요.
3. **틀리면 같은 문제를 다시 고르게 하지 않아요.** 원인 한 줄 + 숫자·배치가 바뀐 **비슷한 새 문제**로.
4. **3초 안에 틀리면** "잠깐! 급하게 누르면 함정에 빠지기 쉬워요. 구하라는 것이 무엇인지 먼저 골라 볼까요?"처럼 생각을 끼워 넣어요.
5. **문제 글만 읽고 답을 알 수 없게.** 판단 근거 낱말(`꼭짓점이 O가 아닌`)을 글에 쓰지 않고 그림으로 판단하게 해요. 강조(굵게·색)는 주어진 것에만.
6. **보기는 4개 이상**, 오답 보기 하나 = 실제 오개념 하나. 숫자 답은 키패드 입력. 2~3지선다는 숙달 판정에 쓰지 않아요.
7. **정답이 둘 이상이면 대칭으로.** 예: 반원 = 부채꼴이면서 활꼴 → 어느 쪽을 먼저 눌러도 "이름이 하나 더 있어요".

### 4-2. 걸음별 기준
| | 🌱 첫걸음 (20점, 찍는 습관) | 🌿 한걸음 (40점, 공식 끼워 넣기) | 🌳 두걸음 (60점, 복합 전략) |
| :--- | :--- | :--- | :--- |
| 구성 | 빠른 구별(그림 보고 고르기) → 선생님과 따라 풀기(한 줄 = 동작 하나) → 도움 없는 비슷한 문제 1개 | 대표 예제(접어 두기) → 빈칸 예시 → 혼자 풀기(겉모습 바꾸기 + 함정 1개 이상) | "이 문제는 무엇 + 무엇?" → 계획표 → 단계 입력 |
| 숫자 | 한 자리 × 한 자리 수준(반지름 2~6, 각 30·45·60·90·120·180°, 좌표 −5~5) | 교과서 수준(약분, π 앞 분수) | 중간 값 칸 + 최종 답 |
| 쓰지 않음 | 복합, 거꾸로 구하기, 3.14, 두 줄 넘는 글 | 처음부터 '친구의 틀린 풀이'(기본 통과 뒤에만) | 공학 도구 관찰, 생활 속 예 찾기 |

- 차시 성격: **개념형**(`arc`·`poly`·`regular`·`rotation`·`rotprop`·`coord`·`graph`)은 구별하기 → 이름 붙이기, 계산 4단계 틀을 쓰지 않아요. **절차형**(`cent`·`sector`·`area`·`volume`·`conearea`·`cone`·`prop`·`inv`)은 부엉 쌤 → 구별 → 따라 풀기 → 혼자 → 마무리.
- 🌳 `어느 두 유형?` 고르기는 **두 유형이 실제로 합쳐진 문제에만**(기본은 꺼져 있고 `comboPick:true`일 때만).

### 4-3. 그림(SVG)
- 흑백 굵은 선 + **주황 `#e08a1e` = 구할 것**, **파랑 `#2a4d9e` = 주어진 것**, 잉크 `#1d2640` = 기본 도형. 글에 쓴 색·점 이름과 그림이 100% 같아야 해요.
- **문제 그림(`quiz:true`)에는 해설 글자 금지**(점 이름·도형·색만). 해설 라벨은 개념 그림에만.
- 비율은 실제 수치대로(120°는 120°처럼). 원호 방향(`sweep-flag`)은 화면에서 눈으로 확인.
- 호의 길이 치수선은 교과서식 `arcDim`(점선 금지). 호 기호 `⌒AB` 등 수학 기호는 글꼴이 아니라 SVG(`<span class="arc-sym">AB</span>`). 자세한 규격은 `AGENTS.md` 6절.
- **움직임은 개념 보기에만, 문제 화면은 정지 그림.** 축하 연출(폭죽 등)은 다 푼 뒤에만.
- **🦉 부엉 쌤 기본 원리 (선생님 결정, 2026-11-28 `T32`)**: 부엉 쌤 말이 가리키는 대상(면·모서리·꼭짓점·호·각 등)은 **반드시 움직임으로 강조**해요. 장면마다 한 줄씩 `beats:[{say, …}]`로 나누고, 그 줄이 말하는 부분만 칠해요.
  - 3D 그림: 박자에 `hl`(그림이 여럿이면 `[그림별 값]`)을 주면 학생이 돌려 놓은 방향 그대로 표시만 바뀌고 **3번 깜빡여요**(엔진 `owlPulse`). 지금 말하는 곳 = 주황, 이미 말한 곳 = 파랑으로 남기기(예: `02t-tracks-solid.js`의 `floorHL`). 가려지는 면은 모서리(`ecol`)로 보여 주기(예: `baseEdgesHL`).
  - SVG 그림: 박자마다 `<g data-b="n">`가 나타나고 `class="dr"` 선은 그려지듯, `ob-pop`·`ob-rot`(T21).
  - 박자 `hl`이 없는 예전 3D 장면도 장면 첫 박자에 칠한 부분이 깜빡이지만, 그건 최소한이에요. 새로 만들거나 고칠 때는 박자별로 가리키는 대상을 정해 주세요.

### 4-4. 학생에게 보이는 말
- 안내·질문·피드백은 **따뜻하고 쉬운 해요체**. 문항 본문은 교과서 문체(`~을 구하시오`).
- 틀렸을 때: 무엇을 잘못 생각했는지 + 바른 생각 한 줄("반지름 대신 지름을 넣었어요. 넓이는 반지름으로 구해요.").
- 맞혔을 때: "잘했어요"보다 과정 칭찬("반지름부터 찾은 게 좋았어요.").
- 설계 용어를 학생 화면에 쓰지 않아요: 사례·비사례 → `맞을까? 아닐까?`, 역산 → `거꾸로 구하기`, 오개념 → `헷갈리기 쉬운 점`, 쌍둥이 → `비슷한 문제`, Step 1 → `1단계`.

### 4-5. 화면·보상
- 홈에는 **오늘 할 일만**, 설정성 카드(나의 길 등)는 내 기록(`#me`)에. 목록 순서는 **고정**(교과서 순서, "최근 것 앞으로" 금지).
- 운에 맡기는 뽑기·포인트 판돈은 늘리지 않아요. 미니게임(숫자야구·좌표 해전·보스 도전)은 유지.
- 교과서 원문·그림·쪽 번호는 저장소에 넣지 않아요(저작권). 교과서 문제 꼬리표 은행은 선생님 컴퓨터 `ai\교과서 문제 꼬리표\`에만 있어요.

### 5-2. 찾아가는 순서
